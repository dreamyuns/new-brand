주석 — ADM-MEM02 (케이스 A)

1
이메일 (읽기전용)
  • 이 서비스는 이메일 인증코드로 로그인하기 때문에, 이메일이 계정을 구분하는 유일한 식별자임 → 수정 불가
  • "인증완료" 배지는 이메일 인증이 완료된 계정임을 항상 표시
정책서 v0.44 8-2절 — 이메일 인증코드 방식
2
이름·성 수정
  • 영문(알파벳)만 입력 가능. 한글 입력 시 유효성 오류 메시지 표시
  • 선택 항목 — 입력하지 않아도 저장 가능
3
국적 변경
  • [변경] 버튼 클릭 → 국가 선택 팝업(바텀시트) 열림 — 프런트 화면 MY03(계정관리) 패턴 참조
  • 국가 목록은 KAYAK Constants API에서 가져온 국가 목록 기반
4
전화번호
  • 국가 코드(예: +82)와 전화번호를 따로 입력. 형식: 010-XXXX-XXXX
  • 숫자와 하이픈(-)만 허용. 선택 항목 — 입력 안 해도 저장 가능
6
포인트 내역 탭 (케이스 C 참조)

  • MVP에서는 조회 전용 — 수동 지급·삭제·회수 없음
어드민 v0.5 6조

주석 — 케이스 C (예약·포인트 내역)

12
예약번호 (BookingID)
  • KAYAK Reporting API에서 내려오는 예약 고유 번호. API 파라미터명: BookingID
  • CS 상담 시 고객이 말하는 예약번호로 내역을 빠르게 찾을 수 있도록 추가한 컬럼
KAYAK Reporting API — BookingID 필드 / 어드민 v0.6 5-3절
13
예약일 (BookingDate)
  • 고객이 예약을 완료한 날짜. API 파라미터명: BookingDate
  • 체크인 날짜와 다름. 예약일은 체크인보다 앞서는 날짜
KAYAK Reporting API — BookingDate 필드
14
호텔명 (HotelName)
  • 예약한 호텔 이름. KAYAK API에서 내려오는 값 그대로 표시. 빈값 → "—" 표시
  • API 파라미터명: HotelName
15
투숙기간
  • 체크인과 체크아웃 날짜를 한 컬럼에 통합해 표시. 예: "07.01 ~ 07.03"
  • API 파라미터명: BookingStartDate(체크인) / BookingEndDate(체크아웃)
  • 포인트 지급완료 기준: 체크아웃 날짜 + 7일 후 자사 배치 실행 시 전환
어드민 v0.6 5-2절 — 적립완료일 = 체크아웃+7일
16
공급사(OTA)
  • 고객이 예약한 타사 예약 사이트 이름. 예: Booking.com, Agoda
  • API 파라미터명: ProviderCode. 코드 → 사람이 읽기 쉬운 이름으로 변환해서 표시
20
포인트(P)
  • 이 예약으로 적립될(된) 포인트 금액. 단위: P(포인트), 1P = 1원
  • API 파라미터명: CashbackAmountLocalised (원화 환산값)
  • CashbackType이 NONE이거나 없는 경우(null): "—" 표시
  • 소수점 이하 버림 처리 — 예: 9,623.4 → 9,623P
어드민 v0.6 5-3절 / 포인트_정책서 v0.1 2-2절
11
타입 (CashbackType)
  • PERCENTAGE: 예약금액의 몇 %를 포인트로 줌
  • FLAT: 예약금액과 관계없이 정해진 포인트 금액을 그대로 줌
  • NONE 또는 없는 경우(null): "—" 표시. 포인트(P) 컬럼도 "—"
어드민 v0.6 5-3절
18
포인트 상태 (자사 정의)
  • 적립예정: 체크아웃+7일 미도래 또는 자사 배치 미실행 상태
  • 적립완료: 체크아웃+7일 후 자사 배치 선적립 처리 완료
  • 취소: KAYAK Cancelled 감지 후 자사 처리 완료. 만료는 Phase 2 이후 정책 확정
어드민 v0.6 5-2절 — 포인트 상태 자사 정의
19
적립완료일
  • 체크아웃 날짜 + 7일로 계산한 날짜. 자사 배치 처리가 완료된 날짜 기준. 형식: YYYY-MM-DD
  • 적립예정 건: 예정일(YYYY-MM-DD) 표시
  • 취소 건: "—" 표시
어드민 v0.7 5-2절·5-3절 — 적립완료일 (체크아웃+7일)
