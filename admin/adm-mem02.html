주석 — 케이스 C (포인트 내역)

12
예약번호 (BookingId)
  • KAYAK Reporting API에서 내려오는 예약 고유 번호. API 파라미터명: BookingId
  • CS 상담 시 고객이 말하는 예약번호로 내역을 빠르게 찾을 수 있도록 추가한 컬럼
  • TransactionType="Booking"인 건에만 존재. Click 건에는 이 값이 없음
KAYAK Reporting API — BookingId 필드
13
예약일 (BookingDate)
  • 고객이 예약을 완료한 날짜. API 파라미터명: BookingDate
  • 체크인 날짜와 다름. 예약일은 체크인보다 앞서는 날짜
  • CS 상담 시 예약 시점을 파악하거나 분쟁 기준일로 활용
KAYAK Reporting API — BookingDate 필드
14
호텔명
  • 포인트가 발생한 예약의 호텔 이름. KAYAK API에서 내려오는 값 그대로 표시
  • API 파라미터명: HotelName (또는 Description 필드 — 개발팀 확인 필요)
15
체크인 / 체크아웃
  • 해당 예약의 체크인·체크아웃 날짜. YYYY-MM-DD 형식으로 표시
  • API 파라미터명: CheckIn / CheckOut
  • 포인트 적립 상태(적립예정 → 적립완료)는 체크아웃 날짜를 기준으로 판단됨
어드민 v0.5 6-2절 — 체크아웃 기준 Approved 전환
16
공급사(OTA)
  • 고객이 예약한 타사 예약 사이트(OTA) 이름. 예: Booking.com, Agoda
  • API 파라미터명: ProviderCode (예: "bookingcom", "agoda")
  • 화면에는 사람이 읽기 쉬운 이름으로 변환해서 표시 (코드 → 표시명 매핑 필요)
17
포인트 금액
  • 이 예약으로 적립된 포인트 금액. 단위: P(포인트), 1P = 1원
  • API 파라미터명: CashbackAmount
  • PERCENTAGE 타입이면 예약금액 × 포인트율(%) 계산값. FLAT 타입이면 고정값 표시
  • 소수점 이하 버림 처리 — 예: KAYAK에서 9,623.4가 내려오면 9,623P로 표시
어드민 v0.5 6-4절 / 포인트_정책서 v0.1 2-2절 — 소수점 버림
11
포인트 타입 배지
  • API 파라미터명: CashbackType
  • PERCENTAGE: 예약금액의 몇 %를 포인트로 줌. 포인트 금액 컬럼에 "(3%)" 형태로 율 표시
  • FLAT: 예약금액과 관계없이 정해진 포인트 금액을 그대로 줌
  • null(캐시백 미지원 공급사): 표 행은 표시하되 포인트 금액 컬럼만 —으로 표시 (2026-08-05 확정)
정책서 v0.44 9-7절 — 포인트 타입 구분
18
상태 배지
  • API 파라미터명: TransactionStatus
  • 적립예정 (TransactionStatus="Active"): 체크아웃 전이거나 아직 자사 기준 통과 전 상태
  • 적립완료 (자사 내부 Approved 판정): 체크아웃 후 자사 배치 처리로 확정된 상태. KAYAK TransactionStatus 값과 직접 대응하지 않음
  • 취소·만료 (TransactionStatus="Cancelled"): 예약 취소 또는 포인트 만료 상태
어드민 v0.5 6-2절 — 상태 정의 및 Approved 판단 기준
19
적립일
  • 포인트가 적립완료(Approved)로 확정된 날짜. API 파라미터명: PaymentMonth
  • 적립예정(Active)·취소(Cancelled) 상태이면 "—"으로 표시
  • KAYAK 기준 미국 동부 시간(EST) 기준이므로 한국 시간(KST)과 최대 13~14시간 차이 가능
