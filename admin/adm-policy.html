제1조 목적 및 MVP 범위
1-1. 서비스 목적

본 정책서는 신규 메타서치 MVP 어드민의 기능·권한·화면 정책을 정의한다.
어드민은 내부 운영팀이 사용하는 관리 도구로, 고객 대면 서비스(프런트)와 독립적으로 운영된다.

1-2. MVP 어드민 1뎁스 구조
#1뎁스MVP 포함비고
1대시보드✅ 낮은 우선순위핵심 수치 요약. 우선순위 낮음 — 공수 확인 후 결정
2회원관리✅회원 목록·상세 조회 + 수정. 탈퇴 회원 기본 정보 조회 포함 (4-2절 항목별 삭제 기준 참조)
3예약내역✅KAYAK Reporting API 예약완료 기준. 목록(adm-book01) + 상세(adm-book02) 2단계 구조. 5절 참조.
4포인트관리✅MVP = 공급사별 현황 조회 전용. 포인트 내역은 예약상세(adm-book02)로 통합. Phase 2 = 상태변경·지급·회수
5어드민 관리자 설정✅마스터 계정 관리. 서브아이디는 Phase 2
6이메일 템플릿 관리✅발송 이메일 텍스트 편집 + 테스트 발송. 9절 참조

4-3. 회원별 예약내역 탭 (연동)

위치: 회원 상세 화면 내 [예약·포인트 내역] 탭 (v0.6 탭명 변경)
내용: 해당 회원의 KAYAK Reporting API 예약완료 내역. 표시 항목은 5-3절(예약내역 목록) 컬럼과 동일
진입: 목록 행 클릭 → 예약상세(5-4절, adm-book02.html)로 이동
연동 방식: p= 파라미터로 삽입한 회원 식별자(labels 필터링) 기반 조회

⚠️ 예약자명·투숙자명 표시 불가: KAYAK Reporting API 응답 필드에 예약자명·투숙자명이 존재하지 않음. 아웃링크를 통해 타 OTA에서 예약 완료된 투숙자 정보는 해당 OTA가 보유하며 자사로 전달되지 않음. 회원 식별은 회원ID 기준으로만 가능.

6-1. MVP 운영 방침

MVP(1단계)는 공급사별 현황 조회 전용으로 운영한다. 포인트 내역 상세는 예약상세(adm-book02)에 통합하며, 별도 포인트 내역 전용 화면(adm-cb01)은 폐지한다. 수동 조정·지급·회수 기능은 Phase 2에 추가한다.

6-3. 공급사별 포인트 현황 (adm-cb02)

공급사 코드별 포인트 발생 건수·합계 금액 집계. 기간 필터 적용 가능.

⚠️ CPC 예외 공급사: 일부 공급사는 CPA 대신 CPC(클릭 시 수수료) 모델로 운영됨. CPC 건은 TransactionType=Click으로 분류되어 포인트 내역 집계에 포함되지 않음. 해당 공급사라도 포인트 지급 내역이 1건 이상 존재하면 공급사별 현황에 계속 표시.
