Phase 2 예정 기능: 포인트 수동 지급 / 삭제 / 회수 기능은 Phase 2에서 추가. MVP에서는 조회만 가능.
⚙ 공통 정책 — 포인트 내역
  • 데이터 소스: KAYAK Reporting API — labels 파라미터로 회원에게 귀속된 포인트 내역을 가져옴 (6조)
  • 표시 대상: TransactionType="Booking" 건만 표시. TransactionType="Click" 건은 표시하지 않음 (6-2절)
  • MVP 조회전용: 포인트 지급·삭제·회수 기능은 없음. Phase 2에서 추가 예정 (6조)
  • 적립완료(Approved) 판단: 체크아웃+7일 후 자사 배치 처리로 자동 전환. KAYAK paymentMonth 값 단독 기준 아님 (6-2절 / 포인트_정책서 v0.1 2-1절)
  • 적립예정(Active) 주의: KAYAK API 상태값은 Active. 체크아웃 전 미확인 상태 (6-2절)
  • 취소·만료(Cancelled): TransactionStatus = Cancelled. PERCENTAGE 타입이어도 포인트 금액 0인 실데이터 케이스 있음 (6-2절)
  • null/0P 건 미표시: CashbackType이 null(미설정) 또는 포인트 금액 0인 건은 이 화면에 표시하지 않음 (6-2절)
  • 금액 단위: P (포인트). 1P = 1원 기준. 소수점 이하 버림 (예: 7,659.42 → 7,659P) (6-4절 / 포인트_정책서 v0.1 2-2절)
  • KAYAK 정산 상태 표시 방식: TransactionStatus(Active/Cancelled) 어드민 별도 표시 여부 미결 — 개발팀 확인 필요 (8조 미결 9)
기준: 어드민 v0.5 6조

주석 — ADM-CB01

1
검색 필드
  • 회원 이메일 주소 또는 예약 ID(예: RES-20001)로 특정 내역을 찾을 수 있음
  • 회원 상세 화면(ADM-MEM02)의 포인트 탭과 같은 데이터를 보여줌. 이 화면은 전체 회원 대상으로 한 번에 조회하는 점이 다름
2
상태 필터
  • 포인트 상태를 세 가지로 구분해 필터링할 수 있음
  • 적립예정 (Active): 아직 체크아웃 전이거나 확인이 안 된 상태. KAYAK 시스템에서 가져오는 상태값은 Active
  • 적립완료 (Approved): 자사 내부 기준(체크아웃 후 일정 기간 경과)에 따라 확정된 상태. KAYAK paymentMonth 값만으로 판단하지 않음 — 자사 정책 우선 적용
  • 취소·만료 (Cancelled): 예약이 취소됐거나 포인트가 만료된 상태. PERCENTAGE 타입이어도 포인트 금액이 0인 실데이터가 존재하므로 타입만으로 금액을 추측하면 안 됨
  • 포인트 금액이 0이거나 CashbackType이 null인 건은 이 화면에 나타나지 않음
어드민 v0.3 6-2절 — Active/Approved/Cancelled 상태 정의 및 Approved 판단 기준 (v0.42)
3
지급월 범위 필터
  • 전체 (디폴트): 라디오에서 "전체" 선택 시 날짜 입력창 비활성(흐림). 전체 기간 포인트 내역 조회
  • 기간 선택: 라디오에서 "기간 선택" 클릭 시 시작월 입력창 활성화
  • 시작월만 입력 → 그 달 1개월치만 조회 (종료월 = 시작월 자동 적용)
  • 시작월·종료월 모두 입력 → 그 범위 내 조회 (예: 2026-05 ~ 2026-07 = 3개월)
  • 종료월 입력창은 시작월 입력 후 활성화됨. 종료월만 단독 입력 불가
  • 날짜 형식: YYYY-MM (예: 2026-06). KAYAK 기준 EST이므로 KST와 최대 13~14시간 차이 가능
4
포인트 타입 배지
  • PERCENTAGE: 예약금액의 몇 % 를 포인트로 줌 (예: 3% → ₩320,000 예약 시 9,600P 적립)
  • FLAT: 예약금액과 상관없이 정해진 포인트를 그대로 줌
  • CashbackType이 null(미설정): 포인트 없음 — 이 화면에 표시하지 않음
  • 주의: PERCENTAGE 타입이어도 예약이 취소(Cancelled)되면 포인트 금액이 0이 될 수 있음. 타입 배지만 보고 포인트 금액을 추측하면 안 됨 (2026-07-06 실데이터 확인)
  • 포인트 금액 소수점 처리: KAYAK API에서 소수점 있는 값 내려올 수 있음 (예: 7,659.42). 화면 표시·DB 저장 모두 소수점 이하 버림 (7,659P)
어드민 v0.3 6-2절 / 6-4절 — NONE 미표시 + 실데이터 주의사항
5
회원 컬럼
  • 포인트를 적립한 회원의 이메일 주소를 표시
  • KAYAK Reporting API에서 labels 파라미터로 회원 귀속 정보를 가져옴. 예약 시 사용자 ID(이메일)를 labels에 담아 API 호출 → 이 값으로 회원을 특정
  • 검색 필드(CN1)에서 이메일을 입력하면 이 컬럼 기준으로 필터링됨
어드민 v0.5 6조 — labels 파라미터 기반 회원 귀속
6
호텔명
  • 포인트가 발생한 예약의 호텔 이름. API 파라미터명: HotelName (또는 Description 필드 — 개발팀 확인 필요)
  • KAYAK API에서 내려오는 값 그대로 표시
7
체크인 / 체크아웃
  • 해당 예약의 체크인·체크아웃 날짜. YYYY-MM-DD 형식으로 표시
  • API 파라미터명: CheckIn / CheckOut
  • 포인트 상태(적립예정 → 적립완료)는 체크아웃+7일을 기준으로 자사 배치 처리 후 전환됨 (포인트_정책서 v0.1 2-1절)
어드민 v0.5 6-2절 — 체크아웃 기준 Approved 전환
8
공급사(OTA)
  • 고객이 예약한 타사 예약 사이트(OTA) 이름. 예: Booking.com, Agoda
  • API 파라미터명: ProviderCode (예: "bookingcom", "agoda")
  • 화면에는 사람이 읽기 쉬운 이름으로 변환해서 표시 (코드 → 표시명 매핑 필요)
9
포인트 금액
  • 이 예약으로 적립된 포인트 금액. 단위: P(포인트), 1P = 1원
  • API 파라미터명: CashbackAmount
  • PERCENTAGE 타입이면 예약금액 × 포인트율(%) 계산값. FLAT 타입이면 고정값
  • 소수점 이하 버림 처리 — 예: 9,623.4 → 9,623P
어드민 v0.5 6-4절 / 포인트_정책서 v0.1 2-2절 — 소수점 버림
10
상태 컬럼
  • API 파라미터명: TransactionType + TransactionStatus 조합으로 판단
  • 적립예정: TransactionType="Booking" + TransactionStatus="Active" → 체크아웃 전이거나 아직 자사 기준 통과 전 상태
  • 적립완료: 체크아웃+7일 후 자사 배치 처리로 포인트 확정. KAYAK TransactionStatus와 직접 대응하지 않음 (포인트_정책서 v0.1 2-1절)
  • 취소·만료: TransactionType="Booking" + TransactionStatus="Cancelled" → 예약 취소 또는 포인트 만료
  • TransactionType="Click" 건은 이 화면에 표시하지 않음
어드민 v0.5 6-2절 — TransactionType/TransactionStatus 정의 및 Approved 판단 기준
11
지급일
  • 포인트가 적립완료(Approved)로 확정된 날짜. API 파라미터명: PaymentMonth
  • 적립예정(Active)·취소(Cancelled) 상태이면 "—"으로 표시
  • KAYAK 기준 미국 동부 시간(EST)이므로 한국 시간(KST)과 최대 13~14시간 차이 가능
어드민 v0.5 6-2절 — 적립완료 기준 날짜
