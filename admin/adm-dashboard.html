⚙ 공통 정책 — 대시보드
  • 우선순위: P2(낮음) — 핵심 화면(회원관리·포인트관리) 구현 완료 후 작업
  • 데이터 소스 혼합: 자사 회원 DB(전체 회원·가입일) + KAYAK Reporting API(예약 건수·포인트)
  • 새로고침 주기: 미확정 — 개발팀과 협의 필요 (예: 페이지 진입 시 1회 / 1시간마다 자동)
  • 포인트 단위: P(포인트), 1P = 1원. 소수점 이하 버림
  • "오늘" 기준: 서버 기준 자정(00:00)부터 현재 시각까지. 시간대(KST/UTC) 기준 개발팀 확인 필요
기준: 어드민 v0.5 3조

주석 — ADM-DASH (참고용)

1
전체 회원 카드
  • 자사 회원 DB 기준. 탈퇴 처리된 회원은 제외한 활성 계정 수
  • "오늘 +N" 서브텍스트: 오늘 자정(00:00)부터 지금까지 새로 가입한 회원 수
  • 데이터 출처: 자사 회원 DB (KAYAK API 아님)
2
총 적립완료 건수 카드
  • KAYAK Reporting API 기반. 서비스 오픈 이후 전체 누적 집계
  • TransactionType="Booking" + 자사 Approved(적립완료) 판정 건수만 집계. Active·Cancelled 건 제외
  • 카드 3번(총 적립완료 포인트)과 동일 기준 — "N건 완료, 총 M원 지급" 구조로 짝을 이룸
  • 기준 날짜(체크아웃+7일 자사 배치 기준)는 개발팀 확인 필요
KAYAK Reporting API — TransactionType="Booking" + 자사 Approved 기준 누적 건수
3
총 적립완료 포인트 카드
  • KAYAK Reporting API 기반. 서비스 오픈 이후 전체 누적 합계
  • 자사 내부 Approved(적립완료) 판정 건의 CashbackAmount 합계만 포함
  • TransactionType="Booking" + 자사 Approved 건만 집계. 적립예정(Active)·취소(Cancelled) 건 제외
  • 소수점 이하 버림 처리. API 파라미터: CashbackAmount
어드민 v0.5 6-2절 — Approved 기준 누적 합계 / 6-4절 — 소수점 버림
4
적립예정 포인트 카드
  • KAYAK Reporting API 기반. TransactionType="Booking" + TransactionStatus="Active" 건의 CashbackAmount 합계
  • 체크아웃 전이거나 자사 Approved 기준 아직 통과 전인 건의 포인트 합계
  • 기간 범위: 전체(누적) 또는 이번 달 — 개발팀과 협의 필요
  • 이 금액은 확정된 포인트가 아님. 취소(Cancelled) 전환 시 줄어들 수 있음
어드민 v0.5 6-2절 — TransactionStatus="Active" 건
5
포인트 적립 현황 — 최신 5건 테이블
  • KAYAK Reporting API 기반. TransactionType="Booking" 건 중 CashbackAmount가 있는 건을 BookingDate 내림차순(최신 먼저)으로 5건 표시
  • 컬럼 정의:
  • 회원 이메일: labels 파라미터 기반 귀속 이메일. 비로그인 건(labels 없음)은 이메일 없이 표시하거나 제외 — 개발팀 확인 필요
  • OTA: ProviderCode 코드값 → 표시명 변환 필요 (예: "bookingcom" → "Booking.com")
  • 포인트 금액: CashbackAmount. 소수점 이하 버림. 취소(Cancelled) 건은 "—" 표시
  • 상태: TransactionStatus 기반. Active=적립예정, Cancelled=취소, 자사 Approved=적립완료
  • [전체 포인트 보기] 버튼 → ADM-CB01(포인트 내역) 이동
KAYAK Reporting API — labels / ProviderCode / CashbackAmount / TransactionStatus
6
최근 가입 회원 — 최신 5명 테이블
  • 자사 회원 DB 기준. 가입일(계정 생성일) 내림차순으로 5명을 가져옴
  • 컬럼 정의:
  • 회원번호: 자사 DB 회원 고유 식별 번호 (예: U-10284). 클릭 시 ADM-MEM02로 이동 — 구현 여부 개발팀 협의 필요
  • 이메일: 인증 완료된 이메일 주소. 로그인 기준값
  • 가입일: 자사 DB 계정 생성 날짜. MM-DD 형식으로 표시 (올해 기준. 전년도 건은 YYYY-MM-DD)
  • [전체 회원 보기] 버튼 → ADM-MEM01로 이동
자사 회원 DB — 가입일 기준 정렬
7
공급사별 현황 테이블
  • 집계 기준: 적립완료일 기준. 조회 기간(최근 1주일/최근 1달)에 따라 해당 기간 내 적립완료(자사 Approved) 건만 집계. 적립예정·취소 건 제외
  • 컬럼 정의:
  • 공급사(OTA): KAYAK ProviderCode → 표시명으로 변환. 예: "bookingcom" → "Booking.com"
  • 적립완료 건수: 해당 기간 내 적립완료(자사 Approved 처리 완료) 건만 집계
  • 포인트 합계(P): 적립완료 건의 CashbackAmountLocalised 합계. 소수점 버림
  • 포인트율/금액: PERCENTAGE 타입은 CashbackValue(%)로 표시, FLAT 타입은 CashbackAmountLocalised(₩)로 표시
  • 타입: CashbackType 값 그대로 표시 (PERCENTAGE / FLAT)
  • 정렬: 적립완료 건수 내림차순 (가장 많이 적립된 공급사 최상단)
  • 빈 데이터: 해당 기간 내 적립완료 건이 없는 공급사는 목록에서 제외
어드민 v0.7 5-1절 — 적립완료일 기준 / KAYAK Reporting API
8
조회 기간 퀵 버튼
  • 대시보드 전체에 공통으로 적용되는 조회 기간 선택 버튼. 각 섹션은 자신의 날짜 기준으로 같은 기간을 계산
  • [최근 1주일]: 오늘 포함 7일간 (오늘 기준 6일 전 ~ 오늘). 기본 선택 상태
  • [최근 1달]: 오늘 포함 30일간 (오늘 기준 29일 전 ~ 오늘)
  • 버튼 옆에 실제 날짜 범위를 YYYY-MM-DD ~ YYYY-MM-DD (오늘) 형식으로 표시. 예: 2026-08-04 ~ 2026-08-11 (오늘)
  • 섹션별 날짜 기준이 다르므로 같은 기간이라도 집계 숫자는 섹션마다 다를 수 있음 — 각 섹션 아래 기준 문구(예약일 기준/가입일 기준/적립완료일 기준) 참조
검색 조건 공통 규칙 — 오늘 기준 최근 1주일(기본) / 최근 1달
