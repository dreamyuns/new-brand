주석 — ADM-BOOK02 (어드민 v0.7 5-4절)

1
예약번호 기반 상세 조회
  • ADM-BOOK01 목록에서 행을 클릭하면 URL 파라미터(예: ?bookingId=RES-20042)를 전달받아 해당 예약 정보를 불러옴
  • 직접 URL 접근 시 bookingId 파라미터가 없으면 목록(ADM-BOOK01)으로 이동 처리 권장
어드민 v0.7 5-4절 — 예약상세 진입 방식
2
블록1 — 예약 기본 정보
  • 예약번호: KAYAK Reporting API BookingID 필드. 고객이 OTA에서 예약 완료 시 KAYAK이 부여하는 고유 번호. CS 상담 시 고객이 말하는 예약번호와 동일
  • 예약일: KAYAK API BookingDate. 고객이 예약을 완료한 날짜(YYYY-MM-DD). 체크인 날짜와 다름
  • 호텔명: KAYAK API HotelName. OTA에서 판매한 호텔 이름 그대로 표시. 빈값 가능 → "—" 표시
  • 도시 / 국가: KAYAK API CityName / CountryCode. 국가는 ISO 2자리 코드(예: KR) 함께 표시
  • 투숙기간: 체크인(BookingStartDate) ~ 체크아웃(BookingEndDate). 박수는 두 날짜 차이로 계산해 자동 표시. 체크인·체크아웃 날짜 정보는 이 블록에서만 확인 (블록4 타임라인에는 날짜 미표시)
  • 공급사(OTA): KAYAK API ProviderCode를 사람이 읽기 쉬운 이름으로 변환해 텍스트 표시. OTA 로고 이미지 없음
어드민 v0.7 5-4절 블록1 / KAYAK Reporting API
3
블록2 — 회원 정보
  • 회원ID: 자사가 아웃링크 URL의 labels 파라미터로 심은 이메일 주소. KAYAK Reporting API에서 해당 예약의 labels 값을 받아와 표시. 이메일이 곧 회원 식별자. 비로그인 상태로 이동한 건: labels 없음 → "—" 표시 (포인트 귀속 불가)
  • 접속기기: 아웃링크 시점의 접속 환경. Mobile 또는 Desktop으로만 구분 표시. OS·브라우저 세부 정보는 표시하지 않음. 데이터 없는 경우 "—"
  • 언어: 고객이 사용 중이던 언어 설정. BCP 47 코드(예: ko = 한국어, en = 영어, ja = 일본어)로 받아 사람이 읽기 쉬운 이름과 함께 표시. 데이터 없는 경우 "—"
어드민 v0.7 5-4절 블록2 / 정책서 v0.45 9절 — labels 파라미터 귀속
4
블록3 — 적립기준금액 & 포인트 정보 (전체 흐름)
  • KAYAK API에서 받은 원시 데이터를 그대로 보여주는 섹션. 자사가 재계산하거나 임의 수정하지 않음
  • 데이터 흐름: KAYAK API 원시값(USD) → KRW 환산(API 제공) → 포인트 계산 → 소수점 버림 → 화면 표시
  • 포인트지급액: KAYAK API CashbackAmountLocalised (KRW 환산 캐시백 금액). 소수점 이하 버림 후 P 단위 표시. 1P = 1원. 예: ₩5,824.7 → 5,824P
  • 캐시백(USD): KAYAK API CashbackAmount. USD 원시 캐시백 금액. PERCENTAGE 타입일 때: 적립기준금액(USD) × 율 / 100. FLAT 타입일 때: CashbackValue 그대로
  • 포인트 상태: 자사 정의 기준. 적립예정(체크아웃+7일 미도래) / 적립완료(자사 배치 처리 완료) / 취소(KAYAK Cancelled 감지)
  • CashbackType=NONE 또는 null인 공급사 건: 캐시백(USD)·포인트지급액·타입/율 모두 "—" 표시
어드민 v0.7 5-4절 블록3 / 포인트_정책서 v0.1 2절
5
적립기준금액(USD) — API 원시값
  • KAYAK API BookingValue 필드. KAYAK이 포인트 계산에 사용하는 기준 금액. USD로 내려옴
  • 고객이 OTA에서 실제 결제한 금액과 다를 수 있음 (OTA 수수료·세금 제외 기준이거나 KAYAK 자체 집계 방식 때문)
  • 소수점 2자리까지 표시. 예: $126.79
  • 정산·대사(회계 확인) 시 이 USD 값을 기준으로 사용
  • 적립기준금액(KRW): LocalisedBookingValue. KAYAK이 제공하는 KRW 환산값. 환율은 KAYAK 적용 환율 사용(자사 환율 아님). 소수점 2자리까지 표시. 예: ₩194,165.39
KAYAK Reporting API — BookingValue / LocalisedBookingValue
6
캐시백 타입 / 율(금액)
  • KAYAK API CashbackType과 CashbackValue를 한 줄에 함께 표시
  • PERCENTAGE: 적립기준금액의 몇 %를 포인트로 지급하는 방식. 표시 형식: "PERCENTAGE · 3%". 포인트 계산식: 적립기준금액(KRW) × CashbackValue(%) / 100
  • FLAT: 예약금액 크기와 관계없이 정해진 금액을 고정으로 지급하는 방식. 표시 형식: "FLAT · $12.00". 율(%) 없음. 포인트 계산식: CashbackValue(USD)를 KRW 환산
  • NONE / null: 이 공급사(OTA)는 캐시백을 지급하지 않는 건. "—" 표시. 포인트지급액도 "—"
KAYAK Reporting API — CashbackType / CashbackValue
7
적립완료일
  • 계산식: 체크아웃 날짜(BookingEndDate) + 7일. 형식: YYYY-MM-DD
  • 고객 체크아웃 후 7일이 지난 뒤 자사 배치 처리가 실행되면 포인트가 실제로 지급됨. 이 날짜가 자사 배치 실행 기준
  • 적립완료 건: 자사 배치가 실제로 실행된 날짜 표시
  • 적립예정 건: 아직 배치 미실행. 예정일(체크아웃+7일 계산값) 표시
  • 취소 건: 포인트 지급 없음 → "—" 표시
어드민 v0.7 5-2절 — 적립완료일 계산 기준 / 포인트_정책서 v0.1 3절
8
포인트 예상만료날짜
  • 고객에게 지급된 포인트가 사라지는(소멸) 예정 날짜
  • 계산식: 적립완료일 + 365일. 예: 적립완료일 2026-07-10 → 예상만료 2027-07-10
  • 적립완료 건: 확정된 적립완료일 + 365일 → 확정 날짜 표시
  • 적립예정 건: 아직 배치 미실행이므로 적립완료일이 확정되지 않음 → 예정 적립완료일 + 365일로 미리 계산하여 날짜 뒤에 "(예상)" 표기. 실제 배치 완료 시 날짜 갱신됨
  • 취소 건: 포인트 없으므로 만료 없음 → "—" 표시
포인트_정책서 v0.1 소멸 기준 — 적립완료일+365일
9
블록4 — 포인트 상태 타임라인
  • 이 예약의 포인트 상태가 어떤 단계를 거치는지 흐름으로 보여줌. 날짜 없이 상태명만 표시. 정확한 날짜는 블록1(투숙기간)·블록3(적립완료일)에서 확인
  • 케이스1 (체크인 전) — 3단계 흐름:
    1. 투숙예정 · 적립예정 — 고객이 아직 체크인을 하지 않은 상태. 포인트 적립 대기 중
    2. 투숙완료 · 적립예정 — 체크아웃이 끝났지만 체크아웃+7일이 아직 지나지 않아 자사 배치 대기 중
    3. 투숙완료 · 적립완료 — 체크아웃+7일 이후 자사 배치가 실행되어 포인트 지급 완료
  • 케이스2 (취소) — 2단계 흐름: 투숙예정·적립예정 상태였다가 → KAYAK에서 Cancelled 감지 → 취소(빨간 X). 포인트 미지급. 체크아웃 후 취소는 별도 정책 없음(취소로 통일)
  • 아직 안 된 단계: 회색 원(○) / 취소됨: 빨간 X(✕)
