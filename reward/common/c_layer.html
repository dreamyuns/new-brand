3. 공통 규칙 R1~R10

확정 · 시범 적용

구현물 안에서 규칙이 흔들리던 곳을 정리했습니다. 「지금 프로토」와 다른 항목은 구현 시 이 규칙을 따릅니다.

R1토스트는 항상 맨 위에 보인다

바텀시트·전체화면 입력·확인창이 떠 있어도 토스트가 그 위에 보여야 합니다.
구현: 토스트 층 번호 95 — 확인창(90)·시트보다 위. 프로토 반영 완료

R2토스트가 연달아 오면 순서대로 하나씩

앞 토스트를 덮어쓰지 않고, 2초씩 차례로 보여줍니다. 같은 문구가 떠 있거나 기다리는 중이면 다시 넣지 않습니다. 기다리는 토스트는 최대 3개이고, 넘으면 가장 오래 기다린 것부터 버립니다.
예: 계정관리에서 추천코드 적용 "실패" 토스트 → 2초 뒤 "저장했어요". 프로토 반영 완료

R3오류 표시 기준 — 입력 실수는 토스트, 처리 실패는 확인창 + [다시 시도]

  • 입력 실수(사용자가 바로 고칠 수 있음): 토스트 또는 입력칸 아래 빨간 글씨
  • 규칙상 막힘(이미 참여함·상한 도달): 토스트
  • 서버 처리 실패(네트워크·서버 오류일 때만): 확인창 — 아이콘 「?」 / 제목 "잠시 후 다시 시도해 주세요" / 본문 2줄 = ① 무엇을 못 했는지 ② 이유 / [닫기] [다시 시도]
항목내용
본문 예① "출석하지 못했어요" ② "서버에 연결하지 못했어요" — 6절 C-FAIL 캡처
붙는 곳 (18가지 · 호출 19곳)혜택 적립 · 퀴즈 문제 불러오기 · 퀴즈 채점 · 계정관리 저장 · 계정관리 추천코드 적용 · 가입 · 본인인증 · 가입 추천코드 적용(가입 직후·다시 시도 2곳) · 검색 · 정렬 다시 불러오기 · 예약 생성 · 예약 뽑기 · 계좌 저장 · 현금 전환 · 픽샵 구매 · 구매 취소 · 출석 · 쿠폰 사용 완료
①번 문구출석 "출석하지 못했어요" · 본인인증 "본인인증을 마치지 못했어요" · 쿠폰 "사용 완료로 표시하지 못했어요" · 퀴즈 "문제를 불러오지 못했어요" · 그 밖은 7절 「서버 처리 실패」 문구
[다시 시도]같은 요청을 한 번 더 보냅니다. 예외 두 가지:
· 가입 — 계정을 이미 만들었으면 그 단계는 건너뛰고 다음 단계부터 이어서 (처음부터 하면 "이미 가입" 오류가 나므로)
· 예약 뽑기 — 실패하면 선물상자를 먼저 닫고 확인창을 띄움. [다시 시도]는 선물상자를 다시 띄움
「이미 출석했어요」 같은 규칙상 막힘·입력 실수는 그대로 토스트입니다. 프로토 반영 완료 · 남은 위험: 서버가 처리한 뒤 응답만 끊기면 [다시 시도]가 같은 일을 두 번 할 수 있음 — 서버 쪽 중복 방지(R7)는 개발 시 필수

R4확인 형태 — 한 번 확인은 중앙 확인창, 여러 단계는 바텀시트

"~할까요?" 한 번 묻고 끝나는 확인은 L-DIALOG로 통일합니다. 체크·사유 선택 등 단계가 이어지는 탈퇴는 L-SHEET-STEP을 유지합니다.
지금 프로토: SNS 연결 해제·계정 통합의 단일 확인이 바텀시트로 되어 있습니다. (해당 기능은 현재 화면에서 들어갈 수 없음 — 회원 묶음에서 정리)

R5되돌릴 수 없는 작업은 확인을 받는다

쿠폰 [사용 완료]는 확인창을 띄웁니다. 로그아웃은 확인 없이 바로 실행합니다(다시 로그인하면 되므로 — PO 확정 2026-10-26).
쿠폰 확인창 — 제목 "사용 완료로 표시할까요?" · 항목 「상품 — 브랜드 상품명」 · 안내 "표시한 뒤에는 되돌릴 수 없어요" · [취소] [사용 완료]. 프로토 반영 완료 · 로그아웃은 확인 없음

R6기기 뒤로가기 — 맨 위 층부터 하나씩 닫는다

  • 확인창 → [취소]와 같은 동작 · 선택형 시트 → 닫기 · 전체화면 입력 → 닫기
  • 단계형 시트(입력 중) → 이탈 확인창 · 2뎁스 화면 → 직전 화면
  • 적립 연출·선물상자·강제 업데이트 중에는 무시합니다.
지금 프로토: 기기 뒤로가기 처리가 없습니다(화면의 [←]만 있음). 안드로이드 앱 출시 시 필수입니다. 구현 시 반영

R7버튼 연타 방지

서버에 요청하는 버튼은 누르는 즉시 잠그고 "처리 중…"으로 바꿉니다. 응답이 오면 풀어 줍니다. 서버도 같은 요청을 두 번 처리하지 않게 막습니다.
확인창 [실행]을 누르면 두 버튼 모두 잠기고 실행 버튼 글자가 "처리 중…"으로 바뀝니다(6절 C-BUSY). 화면 쪽 프로토 반영 완료 · 서버 쪽 중복 방지는 현금 전환만 있음(같은 신청 번호로 두 번 오면 한 번만 처리) — 나머지는 개발 시 필수

R8문구는 해요체로 통일

5절 참고. "구매가 완료되었습니다" 같은 합쇼체, 대시(—), 토스트 속 이모지를 쓰지 않습니다.

R9버튼 순서는 [취소] [실행]

두 버튼이 나란히 있으면 왼쪽이 취소(회색), 오른쪽이 실행(강조색)입니다. 고객앱·어드민 모두 같습니다. 위험한 실행(삭제·반려)은 빨간색.
어드민 모달 전체 [취소] [실행]. 프로토 반영 완료

R10어드민은 자체 모달만 쓴다

브라우저 기본 경고창(confirm·prompt)을 쓰지 않습니다. 입력이 있는 모달은 배경을 클릭해도 닫히지 않습니다(입력값이 날아가지 않게). 8절 참고.
프로토 반영 완료 — 출금 지급·쿠폰 재발행도 자체 모달
