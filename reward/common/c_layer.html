화면 위에 잠깐 뜨거나 화면을 덮는 모든 요소(토스트·확인창·바텀시트·적립 연출·로딩·브라우저 알림창)를 언제 어떤 것을 쓰는지 한곳에 정리했습니다. 각 화면기획서는 이 규칙을 따르고 예외만 따로 적습니다. 규칙(3절)마다 실개발이 지금 어떻게 되어 있는지를 함께 적었습니다.

모양은 디자인 확정 전입니다. 이 문서는 언제·무엇을·어떻게 닫는지를 기준으로 읽어 주세요.

3. 공통 규칙 R1~R10 — 실개발 상태

10-26 PO가 시범 적용한 규칙입니다. 각 규칙 아래 「실개발」 줄이 지금 상태이고, 다름은 규칙과 실개발이 다른 곳입니다(대사 확인 요청 D-12).

R1토스트는 항상 맨 위에 보인다

시트·확인창·적립 연출이 떠 있어도 토스트가 그 위에 보입니다.
실개발: 토스트 층 70 — 확인창·적립 연출(60)·시트(50)·탭바(40)보다 위. 같음

R2토스트가 연달아 오면 순서대로 하나씩

앞 토스트를 덮어쓰지 않고 2초씩 차례로 보여 줍니다(대기 최대 3개).
실개발: 대기열 없음 — 새 토스트가 앞 토스트를 바로 바꿉니다(2초 다시 셈). 예: 필터 초기화 직후 검색 오류가 오면 앞 문구는 사라짐. 다름

R3오류 표시 기준 — 입력 실수는 토스트, 처리 실패는 확인창 + [다시 시도]

  • 입력 실수: 토스트 또는 입력칸 아래 빨간 글씨
  • 규칙상 막힘(이미 참여·상한·없는 코드): 토스트
  • 서버 처리 실패(네트워크·서버 오류): 확인창 — 제목 = 무엇을 못 했는지 / 본문 = 서버가 보낸 이유(없으면 "잠시 후 다시 시도해 주세요") / [닫기] [다시 시도]
실개발: 확인창 + [다시 시도]는 출석("출석하지 못했어요")·퀴즈 채점("채점하지 못했어요") 2곳. 그 밖의 서버 실패는 화면마다 다름 — 가입·탈퇴 시트 안 문구 "요청을 처리하지 못했습니다. 잠시 후 다시 시도해주세요." · 혜택 홍보 페이지 상태 칸 · 추천코드·뽑기·알림 모두 읽음은 토스트 · 검색은 토스트+목록 자리 안내. 다름 (규칙의 「잠시 후 다시 시도해 주세요」 제목 대신 「○○하지 못했어요」 제목)

R4확인 형태 — 한 번 확인은 중앙 확인창, 여러 단계는 바텀시트

실개발: 본인인증 그만두기 · 가입 직후 권유 · 탈퇴 마지막 확인 = 중앙 확인창 / 가입·본인인증·탈퇴 = 단계형 시트. 같음 (SNS 연결 해제는 C21로 화면 없음)

R5되돌릴 수 없는 작업은 확인을 받는다 · 로그아웃은 확인 없이

실개발: 탈퇴는 이메일 재인증 + 사유 + 확인창 · 로그아웃은 확인 없이 바로. 쿠폰 사용 완료는 쿠폰함이 없어 해당 없음. 같음

R6기기 뒤로가기 — 맨 위 층부터 하나씩 닫는다

실개발(웹): 기기 뒤로가기 처리 없음 — 브라우저 뒤로가기는 화면 이동. ESC는 시트·확인창을 닫음. 안드로이드 앱에서 필수 → 앱 인계(C22). 앱 개발 때

R7버튼 연타 방지 — 화면은 누르는 즉시 잠그고, 서버도 두 번 처리하지 않는다

실개발 화면: 출석·퀴즈 O/X·추천코드 [입력]·가입·본인인증·탈퇴·뽑기 상자 — 요청 중 잠금. 서버: 출석·퀴즈(하루·문항당 1회) · 혜택(회원당 1회) · 뽑기(예약당 1회 조건부 저장) · 추천코드(회원당 1회) · 홍보 페이지 시작(한 문장 저장) 모두 두 번째 요청을 막음. 같음

R8문구는 해요체로 통일

5절 참고.
실개발: 리워드 화면 문구는 해요체. 리워드 이전부터 있던 문구에 합쇼체가 남아 있음 — "요청을 처리하지 못했습니다…" · "저장하지 못했습니다…" · "저장되었습니다" · "링크가 복사되었습니다" · "최대 8객실까지 추가 가능합니다" · "필터가 적용됐습니다" · "총 N개 숙소가 모두 표시됐습니다" · "영문 알파벳만 입력 가능합니다" · "로그인이 유효하지 않습니다…". 다름

R9버튼 순서는 [취소] [실행]

두 버튼이 나란히 있으면 왼쪽이 취소(회색), 오른쪽이 실행(강조색).
실개발 고객 웹 확인창: 왼쪽 취소 · 오른쪽 실행. 같음 · 어드민은 8절(어드민 차례에 확인)

R10어드민은 자체 모달만 · 입력 모달은 배경 클릭으로 닫히지 않음

어드민 실개발 확인은 어드민 화면기획서를 다시 쓸 때 함께 합니다(8절). 참고: 고객 웹 확인창은 배경 누르기·ESC로 [취소]처럼 닫힙니다(입력이 있는 확인창은 없음). 어드민 차례

4. 여러 개가 겹칠 때

쌓이는 순서 (위가 위)

하단 탭 · 떠 있는 버튼 40
바텀시트 · 검색 풀시트 50
중앙 확인창 · 적립 연출 · 뽑기 상자 · 선물상자 60

숫자는 실개발의 층 번호(z-index). 확인창이 시트보다 위라 "본인인증을 그만둘까요?"가 시트 위에 뜹니다.

순서 규칙

  • 확인창은 대기열 — 떠 있는 동안 새 확인창이 오면 앞 것을 닫은 뒤 차례로.
  • 토스트는 대기열 없음 — 가장 마지막 것만 보입니다(R2 다름).
  • 적립 연출은 본인인증 시트가 닫힌 뒤에 뜹니다(적립대기 지급 → 연출 → 하려던 참여).
  • 선택 시트·필터 창·AI 검색이 열리면 [적립필독] 떠 있는 버튼을 숨깁니다.
  • 시트가 하나라도 열려 있으면 뒤 화면 스크롤을 잠급니다(시트 안에서 끝까지 밀어도 뒤 화면이 안 움직임).
