화면 주석 — MODAL-A

진입
비로그인 [이동→] 탭 시 바텀시트 슬라이드업
  • 비로그인 상태에서 S01 검색결과 카드의 [이동→] 버튼 탭 시, 또는 S02 가격비교 탭의 [이동→] 버튼 탭 시 이 모달이 아래에서 슬라이드업으로 나타납니다.
  • 배경 화면(S01/S02)은 흐릿하게(블러) 처리되고, 어두운 반투명 막이 깔립니다.
  • 포인트가 있는 공급사(cashback.type = PERCENTAGE 또는 FLAT)이면 이 화면(MODAL-A) — 포인트 적립 안내 포함.
  • 포인트가 없는 공급사(cashback.type = NONE)이면 MODAL-B — 포인트 안내 없이 기본 로그인 유도만.
  • 이미 로그인한 사용자는 이 모달 없이 바로 OUT01(이동 중 화면)으로 진입합니다.
정책서 7-1절 / 9-7절.
1
[✕] 닫기 버튼
  • 탭 시 모달이 아래로 슬라이드되어 닫힙니다.
  • S01(검색결과) 또는 S02(숙소 상세) 화면으로 돌아갑니다.
  • 외부 예약 사이트로 이동하지 않습니다.
  • 닫은 후에도 검색결과를 계속 둘러볼 수 있습니다.
정책서 7-1절.
2
브랜드 캐릭터 일러스트
  • 연한 파란 원형 배경 안에 픽콕 브랜드 캐릭터 이미지를 표시합니다.
  • 모달 상단에서 사용자의 시선을 자연스럽게 잡아주는 역할입니다.
  • MODAL-A와 MODAL-B 모두 동일한 캐릭터를 사용합니다.
정책서 7-1절.
3
포인트 예상 적립금액 — 파란색 강조 표시
  • 판매가와 포인트 적립률을 곱해서 얼마를 받을 수 있는지 미리 보여줍니다. 소수점 이하는 버립니다.
  • 로그인하지 않아도 "이 정도 포인트 혜택이 있다"는 걸 보여줘서 로그인을 유도하는 목적입니다.
  • PERCENTAGE 타입 계산식: 판매가(원화) × 적립률(%) ÷ 100 → 소수점 버림 = 포인트 수치 표시. 예: 402,000 × 5.5% = 22,110 포인트
  • FLAT 타입: KAYAK이 제공한 고정 포인트금액을 그대로 표시합니다.
  • 수치 텍스트만 파란색(#2563eb)으로 강조하고, "로그인하면 최대"와 "가 적립돼요"는 검정 일반 텍스트입니다.
← providers[selectedProviderIndex].cashback.type / .value × results[selectedIndex].totalRate → 포인트 수치 계산
정책서 v0.45 9-7절 / 포인트_정책서 v0.1 적립 계산식.
◼ PERCENTAGE 5.5% + 판매가 402,000원 → "로그인하면 최대 22,110 포인트가 적립돼요"
◼ FLAT 10,000포인트 → "로그인하면 최대 10,000 포인트가 적립돼요"
◼ NONE → MODAL-B로 분기 (포인트 헤드카피 없음)
4
서브텍스트 — 포인트 안내 문구
  • "적립 포인트는 판매사 정책에 따라 달라질 수 있습니다." — MODAL-A에서만 표시합니다.
  • 예상 포인트가 정확한 약속이 아닌 추산값임을 알려주는 작은 안내 문구입니다.
  • KAYAK 공급사별로 적립률이 달라질 수 있기 때문에 표기합니다.
  • MODAL-B(포인트 없는 경우)에는 이 서브텍스트가 없습니다.
정책서 7-1절 / 9-7절.
5
호텔 정보 카드
  • 사용자가 탭했던 공급사·호텔이 무엇인지 바로 확인할 수 있도록 카드 형태로 표시합니다.
  • 표시 항목: 호텔 대표 이미지(썸네일) / 호텔명 / 공급사명 / 체크인~체크아웃·박수·투숙객 수·객실 수 / 총 가격
  • 가격은 카드 우측 하단에 굵게 표시합니다.
  • S01/S02에서 이미 불러온 데이터를 그대로 재사용합니다 — 외부 서비스에 다시 요청하지 않습니다.
← S01/S02 카드 데이터 재활용 (hotelName, providerName, checkIn, checkOut, nights, guestCount, roomCount, totalRate)
정책서 7-1절.
6
[로그인하고 혜택받기] 버튼
  • 탭 시 이 모달이 아래로 닫히고, AUTH 로그인/회원가입 통합 바텀시트가 올라옵니다.
  • 로그인하기 전에 탭했던 공급사 정보(예약 URL 등)는 임시 저장되어, 로그인 완료 후 자동으로 이동 화면(OUT01-A)으로 진행됩니다.
  • 사용자가 이미 탭해 두었던 과정이 로그인 후 자동으로 이어집니다.
정책서 7-1절 (버튼 단일화) / 8-1절 (로그인·회원가입 통합 바텀시트).
7
[혜택 없이 계속하기] 건너뛰기
  • 로그인하지 않은 채로 외부 예약 사이트로 바로 이동합니다 (OUT01-A2, 비로그인 케이스).
  • 이동 URL에 userTrackId가 포함되어 있어서, 로그인하지 않아도 예약이 완료되면 우리 서비스에 수익(CPA)이 발생합니다.
  • 단, 회원 계정과 연결되지 않으므로 포인트 적립은 이루어지지 않습니다.
  • 강제 로그인을 막는 원칙에 따라 이 텍스트는 항상 표시되어야 합니다.
강제 로그인 금지 원칙 / 건너뛰기 항상 노출 — 정책서 7-3절.

화면 주석 — MODAL-B

차이
MODAL-A vs MODAL-B 차이점
  • 탭한 공급사의 cashback.type = NONE이면 이 MODAL-B가 나타납니다.
  • 포인트 적립을 구체적으로 알려줄 근거가 없으므로, "예약 내역 저장"이라는 실용적인 이유로 로그인을 권유합니다.
  • 버튼 구조([로그인하고 혜택받기] + [혜택 없이 계속하기])와 호텔 정보 카드는 MODAL-A와 같습니다.
  • MODAL-A와의 차이: 포인트 수치 헤드카피 없음, 서브텍스트 없음, 헤드카피 문구 다름.
← providers[selectedProviderIndex].cashback.type = NONE → MODAL-B 표시
정책서 7-1절 / 9-7절.
1
브랜드 캐릭터 일러스트
  • MODAL-A와 동일한 픽콕 캐릭터를 동일한 스타일(연한 파란 원형 배경)로 표시합니다.
  • 포인트 유무와 관계없이 브랜드 일관성을 유지합니다.
정책서 7-1절.
2
기본 로그인 유도 헤드카피
  • "로그인하고 예약 내역을 편리하게 저장해요" — 포인트 수치 강조 없이 예약 내역 저장이라는 실용적 혜택을 안내합니다.
  • 파란색 강조 텍스트 없음. 헤드카피 전체가 검정색입니다.
  • 서브텍스트("적립 포인트는 판매사 정책에 따라...") 없음.
  • 사용자에게 강압적이지 않게 로그인을 권유하는 표현입니다.
정책서 7-1절.
3
[혜택 없이 계속하기] 건너뛰기
  • MODAL-A의 건너뛰기와 동일하게 동작합니다.
  • 로그인하지 않은 채로 외부 예약 사이트로 이동합니다 (OUT01-A2 비로그인 케이스).
  • userTrackId 포함으로 CPA 수익 추적은 유지되며, 포인트 적립은 이루어지지 않습니다.
  • 강제 로그인을 막는 원칙에 따라 항상 표시됩니다.
강제 로그인 금지 원칙 / 건너뛰기 항상 노출 — 정책서 7-3절.
